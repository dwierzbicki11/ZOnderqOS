# SMT Stage 20 — live cross-CPU thread handoff

Stage 20 extends the verified ready-thread migration from Stage 19 to a
thread that is already running on an application processor. The source CPU,
not the BSP, must own the saved interrupt context and publish it to the
destination queue while interrupts are masked. The destination CPU is then
woken through the scheduler IPI path and resumes exactly that saved context.

The handoff protocol must preserve these invariants:

- only the source CPU may detach its current running thread;
- the thread is visible in exactly one place: source current slot,
  handoff slot, or destination run queue;
- `StackPointer`, `CpuId`, Stride pass/remain and ticket accounting move as
  one interrupt-owned transaction;
- pinned, blocked, dead and idle threads cannot be migrated;
- OrionGC/STW may observe either owner, but never lose or scan the stack
  twice as two simultaneously running contexts;
- a failed or stale request leaves the source thread runnable and can be
  retried without duplicating queue membership.

The QEMU proof will run an unpinned managed worker on AP1, request migration
to another AP while its LAPIC timer is active, require source-side context
capture and destination-side resume, and then repeat the handoff across the
available AP set. Each hop must advance a checksum after resumption, survive
timer preemption, participate in a real OrionGC collection, exit normally,
and restore all per-CPU idle contexts plus the global thread registry.

The required runtime gate remains QEMU `1S/4C/2T`; the 1-vCPU job is a
regression/no-AP gate, and ARM64 remains a compile regression until the
architecture has an equivalent cross-CPU scheduler-IPI transport.
