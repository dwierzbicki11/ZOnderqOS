# SMT Stage 21 — automatic SMP load balancing

Stage 21 replaces the BSP-scripted live handoff sequence from Stage 20 with
owner-CPU balancing decisions made from timer context. A CPU may mutate only
its own current slot and run queue. Cross-CPU target selection therefore uses
small volatile load snapshots published by each queue owner, never direct
enumeration of another CPU's `List<SchedulerThread>`.

On every scheduler tick, the owner publishes the number of queued non-idle
threads plus its currently running non-idle worker. The source CPU selects the
least-loaded parked AP from these allocation-free snapshots. A compare/exchange
reservation prevents two sources from choosing the same stale target, a load
difference of two is required before moving work, and both CPUs receive a
50-ms cooldown after handoff to prevent ping-pong.

The migration itself reuses Stage 20's proven path: the source timer saves the
live IRQ continuation, moves the ready thread through the installed scheduler,
switches the source to its next runnable thread, and delays the destination IPI
until the common interrupt epilogue is no longer using the outgoing stack. The
explicit Stage 20 mailbox remains higher priority and unchanged.

The Stage 21 runtime gate requires:

- automatic least-loaded target selection with hysteresis;
- no migration of pinned, idle, blocked, sleeping or dead threads;
- source-owned context capture and the verified Stage 20 delayed IPI handoff;
- decisions from both an overloaded low-numbered and high-numbered AP rather
  than a fixed BSP-authored target sequence;
- real AP-local timer preemption before and after balancing;
- OrionGC/STW while ownership changes, with every remote stack scanned once;
- clean worker retirement, idle restoration and global registry restoration;
- QEMU `1S/4C/2T`, 1-vCPU regression, Cosmos 3.0.85 package/ISO builds and
  ARM64 compile regression.

The QEMU proof creates four workers on AP1 and four on the highest AP. It
requires both owner CPUs to initiate balancing, at least four live migrations,
at least three distinct destinations, two timer observations per worker,
resumption of every migrated continuation, one full OrionGC collection with
all AP stacks scanned, and final restoration of idle ownership and the global
thread registry. A single-CPU run remains an explicit no-AP-work regression.

Stage 21 is complete only after the workflow passes for both 1 vCPU and the
required `1S/4C/2T` topology; the implementation checkpoint alone is not a
runtime claim.
