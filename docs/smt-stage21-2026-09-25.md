# SMT Stage 21 — automatic SMP load balancing

Stage 21 replaces the BSP-scripted live handoff sequence from Stage 20 with
owner-CPU balancing decisions made from timer context. A CPU may mutate only
its own current slot and run queue. Cross-CPU target selection therefore uses
small volatile load snapshots published by each queue owner, never direct
enumeration of another CPU's `List<SchedulerThread>`.

The first checkpoint adds the publication primitive. On every scheduler tick,
the owner publishes the number of queued non-idle threads plus its currently
running non-idle worker. This establishes an allocation-free, lock-free read
side for target selection while leaving queue mutation under the existing
owner interrupt discipline.

The completed runtime gate will require:

- automatic least-loaded target selection with hysteresis;
- no migration of pinned, idle, blocked, sleeping or dead threads;
- source-owned context capture and the verified Stage 20 delayed IPI handoff;
- repeated bidirectional movement rather than a fixed AP1-to-AP7 script;
- real AP-local timer preemption before and after balancing;
- OrionGC/STW while ownership changes, with every remote stack scanned once;
- clean worker retirement, idle restoration and global registry restoration;
- QEMU `1S/4C/2T`, 1-vCPU regression, Cosmos 3.0.85 package/ISO builds and
  ARM64 compile regression.

This checkpoint does not claim the Stage 21 runtime proof yet.
