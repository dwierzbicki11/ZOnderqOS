# SMT Stage 18 — concurrent AP scheduling and per-CPU run queues

Stage 18 starts from the verified Stage 17 head
`5f28dd8da8e4d0e8226944ee79fe50b47edd476c`. Stage 17 proved AP-local
timer preemption and saved-context resume on all seven APs, but deliberately
dispatched one AP at a time because the global live-thread registry and exited
runtime accounting are not yet safe for concurrent AP lifecycle changes.

## Runtime proof

On QEMU `1S/4C/2T`, Stage 18 must prove this complete sequence:

1. create and enqueue at least two pinned managed workers for every AP;
2. release all AP dispatch commands as one concurrent generation;
3. let every AP select only from its own Stride run queue;
4. preempt and resume both workers through repeated AP-local timer ticks;
5. overlap worker execution across APs, demonstrated by a shared start barrier
   that cannot complete unless all seven APs are running managed workers;
6. exit every worker through the ordinary scheduler lifecycle and return every
   AP to its enrolled idle context;
7. leave all per-CPU run queues empty except for the active idle contexts and
   retain a complete, duplicate-free global thread registry/GC stack view.

The proof must record per-CPU dispatch, preemption, resume and completion
counters plus deterministic worker checksums. Native mailboxes may coordinate
the concurrent generation, but may not replace scheduler queues or manufacture
runtime completion.

## Required implementation work

- Make the global live-thread registry and exited-runtime accounting safe when
  different APs create, exit and unregister threads concurrently.
- Audit lock ordering between the global registry lock and each `PerCpuState`
  lock; interrupt-side context switches must remain allocation-free and must
  not acquire a lock that can be held by a preempted thread on the same CPU.
- Keep each Stride run queue owned by exactly one CPU in this stage. Cross-CPU
  migration and load balancing remain disabled until concurrent local queues
  are stable.
- Extend the parked-AP native command protocol with a generation-based
  broadcast start/completion handshake so all APs run concurrently rather
  than through the Stage 16/17 sequential helper.
- Run a real OrionGC collection while the concurrent workers are live and
  confirm the stop-the-world snapshot sees every registered worker stack.

## Required gates

- patch apply, reverse-check and idempotence against Cosmos v3.0.85;
- clean patched Cosmos package build and local-feed verification;
- x64 ISO build;
- QEMU Nehalem 1-vCPU regression;
- QEMU Nehalem `1S/4C/2T` concurrent runtime proof and stability interval;
- all Stage 0–17 serial regressions;
- ARM64 managed compile regression.
