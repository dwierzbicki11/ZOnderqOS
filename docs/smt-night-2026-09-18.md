## Work item: Stage 4 native AP bootstrap

### Goal

Release each x64 Limine application processor into a minimal native-only entry,
give it a dedicated stack and dense GS-local CpuId, collect a bounded READY
handshake, and park it without enabling interrupts or entering managed code.

### Files changed

- `patches/cosmos-smt/0004-ap-bootstrap-parked.patch`
- `tools/prepare-cosmos-smt.sh`
- `tools/smoke-stage04-qemu.sh`
- `.github/workflows/smt-stage04.yml`
- this report

### Technical changes

- Adds a 16 KiB native stack per possible xAPIC CpuId and cache-line-separated
  native AP bootstrap state.
- Publishes the Limine `goto_address` with an atomic compare/exchange only
  after state initialization.
- AP entry executes `cli`/ `cld`, switches stack, initializes the Stage 3
  GS slot, records LAPIC/CpuId/stack/RFLAGS, atomically reports READY, and parks
  in `cli; hlt`.
- BSP uses one TSC-bounded deadline, validates every descriptor and AP report,
  rejects duplicate stacks and mismatched LAPIC/GS identities, and emits
  `[SMP-BOOT] PASS` only after all APs are ready.
- The stage explicitly does not run the scheduler, interrupts, GC, or managed
  runtime on APs.

the repository plan: prove that every AP executes a BSP-issued native task.
The patch uses a cache-line-local command/counter/done mailbox per dense CpuId.

## Possible race conditions and unsafe assumptions

- Stage 4 is legacy xAPIC-only and limits CpuId to 0..255.
- BSP must be dense CpuId 0, assigned by Stage 2.
- Limine must enter `goto_address` with the CPU descriptor in RDI, per its x64
  MP protocol ABI.
- APs inherit sufficient descriptor-table state from Limine for the native
  entry; interrupts remain disabled.
- TSC must advance consistently enough for the bounded BSP wait.
- AP stack/state storage is static and intentionally retained for the lifetime
  of the kernel.

## Recommended next step

Design an isolated fixed-IPI delivery/acknowledgement path with AP-local LAPIC
and IDT state, bounded waits and a native-only handler. Keep the existing
counter proof intact and do not begin SMP scheduler or GC work before the IPI
foundation is verified in the same 1-vCPU/1S-4C-2T clean-build matrix.
