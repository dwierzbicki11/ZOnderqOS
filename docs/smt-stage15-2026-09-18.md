# SMT Stage 15 — AP idle-stack enrollment and remote GC scanning

Date: 2026-09-18
Base: Stage 14 PR #64 (`dace06b10e6a31141e5bfdf59b64556fc275fcde`)
Cosmos base: `v3.0.85` (`109ec2aacf2226b8cef53ab496920a285b626848`)
Branch: `smt/stage15-ap-idle-stack`

## Goal

Bind every x64 application processor's dedicated native bootstrap stack to its
already registered scheduler idle-thread record. Prove that a real OrionGC
collection scans each remote stack from the RSP captured by the Stage-10
stop-the-world rendezvous while the AP remains parked.

This stage does not dispatch a managed user thread on an AP. It does not add
AP scheduler ticks, context switching, migration, load balancing or
preemption. The only value deliberately resident on an AP stack during the
proof is a deterministic native canary; no managed reference is held there.

## Implementation

- Enrolls the exact 16-KiB native AP stack bounds in each AP idle
  `SchedulerThread`; the stacks were allocated by Stage 4 and are checked for
  alignment, non-zero bounds and one-time enrollment.
- Adds native command 8 and a cache-line-isolated mailbox per AP. Each AP
  pushes a deterministic canary, publishes `parked`, enables interrupts and
  waits in HLT.
- Extends the GC's non-current `Running`-thread path on x64. A remote stack is
  scanned only when the native rendezvous reports state `parked`; its captured
  RSP must fall inside that thread's registered stack bounds.
- Corrects the x64 rendezvous snapshot to load the interrupted RSP value from
  the AP interrupt frame instead of recording the address of that frame slot.
- Records the number of remote stacks, the exact byte count, the XOR of each
  first live word and a diagnostic XOR of all words passed through the
  conservative scanner.
- Runs one real `GarbageCollector.Collect()`, releases every AP, verifies the
  restored canaries, and requires the stack-start fingerprint to equal their
  XOR.
- Keeps ARM64 CPU0-only: the managed ARM64 projects compile, but no ARM64 SMP
  runtime claim is made.

## Required runtime evidence

For `1S/4C/2T`, the gate requires seven distinct aligned stack ranges and this
ordered evidence:

```text
[SCHED-AP-STACK] begin
[SCHED-AP-STACK] cpu=1 base=0x... top=0x... size=16384 state=enrolled
...
[SCHED-AP-STACK] dispatch
[GC-SMP] STOP epoch=N
[GC-SMP] RESUME epoch=N aps=7
[SCHED-AP-STACK] cpu=1 saved-rsp=0x... span=... canary=0x... state=gc-scanned-returned-native-idle
...
[SCHED-AP-STACK] gc-collection=N scanned=7 bytes=... start-word-xor=0x... word-xor=0x...
[SCHED-AP-STACK-TEST] PASS
```

The parser independently checks every canary value, stack size/alignment,
non-overlap, each captured RSP and its exact span to the enrolled stack top,
the summed GC byte count, stop/resume epoch, AP set, and the fingerprint of the
first live word scanned from every AP stack. The full-range fingerprint remains
diagnostic because live native words above the canary are ABI-dependent. The
1-vCPU regression requires `cpu=0 state=bsp-only`, zero remote scans and no SMP
rendezvous.

## Validation gates

- fresh Stage 1..15 preflight and apply from pinned Cosmos `v3.0.85`;
- repeated apply/idempotence and Stage-15 reverse-apply check;
- patched-tree `git diff --check`;
- Bash syntax and native x64 assembly syntax;
- clean patched Cosmos package build and isolated local NuGet feed;
- ARM64 managed compile regression (no ARM64 SMP/runtime claim);
- real x64 ISO;
- QEMU 1 vCPU and `1S/4C/2T`, including the complete Stage-14 regression and
  30-second late-fault stability interval.

## Review boundary and next stage

Stage 15 makes remote AP idle stacks explicit and GC-visible, but the AP still
returns to the native parked loop. The next safe stage is a persistent managed
AP idle entry with a registered execution context and thread identity, still
without selecting ordinary runnable threads. Only after that remains stable
across GC should AP-local scheduler timer dispatch and real context switching
be introduced as separate stages.
