# SMT Stage 19 — ready-thread migration and load balancing

Stage 19 builds on the verified concurrent per-CPU queues from Stage 18.
It creates all unpinned AP workers on one overloaded Stride queue, invokes
the policy balancer while the AP generation is quiescent, and requires an
even two-worker distribution across every AP queue before dispatch.

The runtime proof then starts all APs together. Every migrated worker must
execute on its new `CpuId`, survive at least two local timer preemptions,
participate in a real OrionGC stop-the-world collection, exit through the
normal scheduler lifecycle, and restore both the global registry and every
AP idle context. The 1-vCPU profile remains a regression gate; the required
SMP proof uses QEMU `1S/4C/2T`.

Migration in this stage is intentionally limited to ready threads while all
owner APs are parked and their scheduler timers are masked. Live cross-CPU
migration needs a separate IPI-owned handoff protocol and is not claimed by
this stage.
